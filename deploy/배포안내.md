# 가톨리미 배포 안내 (한국 리전 VPS + 무료 HTTPS 주소)

구성: **우분투 서버 1대**에 Node.js 앱(`systemd` 서비스)과 **Caddy**(HTTPS 인증서 자동 발급·갱신)를 올립니다.
주소는 도메인 없이 서버 IP로 만드는 무료 주소 `https://<IP를-대시로>.sslip.io` 를 씁니다 (예: `3.35.12.34` → `https://3-35-12-34.sslip.io`).

학교 사이트를 수집해야 해서 **서울 리전**을 권합니다. 서버는 상시 실행되어야 하고(30분마다 수집·푸시), SQLite 파일을 저장할 디스크가 필요합니다.

---

## 1. 서버 만들기 (AWS Lightsail 서울 기준, 약 10분)

1. https://lightsail.aws.amazon.com 에 로그인 → **인스턴스 생성**
2. 리전: **서울 (ap-northeast-2)**
3. 플랫폼 **Linux/Unix** → 블루프린트 **OS 전용 → Ubuntu 24.04 LTS**
4. 플랜: 메모리 **1GB** 플랜 권장 (512MB도 동작은 함). 이름 예: `catolimi`
5. 만든 뒤 인스턴스 → **네트워킹** 탭
   - **고정 IP 생성 후 연결** (재시작해도 주소가 바뀌지 않게 — 주소가 바뀌면 HTTPS 주소도 바뀝니다)
   - **IPv4 방화벽**에 **HTTPS (443)** 추가 (SSH 22, HTTP 80 은 기본으로 열려 있음)
6. 오른쪽 위 계정 메뉴 → **계정 → SSH 키** → 서울 리전 **기본 키 다운로드** (`LightsailDefaultKey-ap-northeast-2.pem`)

> Oracle Cloud(무료 VM)를 쓸 때: 리전 춘천/서울, 이미지 Ubuntu, 사용자 이름 `ubuntu`. VCN 보안 목록(Security List)의 수신 규칙에 TCP 80·443 을 추가하세요. 서버 안쪽 iptables 는 `setup.sh` 가 열어 줍니다.

## 2. 배포 (이 PC에서 한 줄)

프로젝트 폴더에서 PowerShell:

```powershell
.\deploy\deploy.ps1 -Server <고정IP> -Key <다운로드한 .pem 경로>
```

처음에는 3~5분 걸립니다(Node.js·Caddy 설치, 테스트 27개, 서비스 등록). 끝나면 `완료 → https://...sslip.io` 가 나옵니다.

- 이 PC `.env` 의 **DeepL·Claude API 키만** 골라 서버 `.env` 에 넣습니다 (`-NoKeys` 로 끌 수 있음). 관리자 토큰·푸시(VAPID) 키는 서버에서 새로 만듭니다.
- 처음 배포 때 **지금까지 수집한 공지 DB 사본**을 함께 올려서 첫 수집을 기다리지 않아도 됩니다 (`-NoData` 로 끌 수 있음). 서버에 DB가 생긴 뒤에는 올리지 않습니다.
- 가진 도메인을 쓰려면 DNS A 레코드를 서버 IP로 맞춘 뒤 `-Domain notice.example.com` 을 붙이세요.

**업데이트**도 같은 명령입니다. 코드만 바꾸고 서버의 `.env`·DB는 그대로 둡니다. 테스트가 실패하면 서비스를 바꾸지 않고 멈춥니다.

## 3. 배포 뒤

| 하고 싶은 것 | 명령 (서버에서) |
|---|---|
| 접속 | `ssh -i <키.pem> ubuntu@<IP>` |
| 로그 보기 | `sudo journalctl -u catolimi -f` |
| 재시작 | `sudo systemctl restart catolimi` |
| 관리자 토큰 확인 | `sudo grep ADMIN_TOKEN /opt/catolimi/.env` |
| 지금 바로 수집 | `curl -X POST -H "Authorization: Bearer <토큰>" https://<주소>/api/admin/crawl` |
| 설정 바꾸기 | `sudo nano /opt/catolimi/.env` → `sudo systemctl restart catolimi` |

- 휴대폰에서 주소를 열고 **홈 화면에 추가**하면 앱처럼 설치되고, 설정에서 푸시를 켤 수 있습니다 (iPhone은 홈 화면에 추가한 뒤에만 푸시 가능).
- 운영 전에 학교 정보 담당 부서에 수집 사실을 알리는 것을 권합니다. 수집 요청에는 `CatolimiBot/0.1 (student project; https://<주소>)` 가 표시됩니다. 연락처를 넣으려면 `.env` 의 `CRAWL_USER_AGENT` 를 바꾸세요.

## 4. 테스트 서버 (develop 자동 배포)

`develop` 에 PR 이 머지되면 GitHub Actions(`.github/workflows/deploy-staging.yml`)가 **테스트 서버**에 자동으로 배포합니다. 진짜 API 키는 GitHub 과 테스트 서버에만 있어서, 개발자는 키 없이 테스트 서버 주소로 접속해 실제 Claude 분석·번역·푸시를 확인합니다 (CONTRIBUTING.md 4절 통합 테스트).

테스트 서버는 운영 서버와 **같은 VPS 에 따로** 설치됩니다 (다른 VPS 를 써도 됩니다).

| | 운영 | 테스트 서버 |
|---|---|---|
| 배포 | `deploy.ps1` (master 에서) | develop 머지 시 자동 |
| 폴더 · 서비스 | `/opt/catolimi` · `catolimi` | `/opt/catolimi-staging` · `catolimi-staging` |
| 주소 | `https://<IP>.sslip.io` | `https://staging.<IP>.sslip.io` |
| 수집 주기 | 30분 | 3시간 (학교 사이트 부담을 줄이려고) |
| 처음 DB | 이 PC 의 수집 DB | 같은 서버 운영 DB 의 공지 사본 (**푸시 구독·발송 기록·오류 신고는 지움**) |
| 푸시 키 | 운영 키 | 따로 만든 키 (운영 사용자에게 알림이 가지 않음) |

### 처음 한 번 설정 (저장소 관리자)

1. **배포용 SSH 키 만들기** (개인 `.pem` 을 GitHub 에 넣지 않으려고 배포 전용 키를 따로 만듭니다). 이 PC PowerShell:
   ```powershell
   ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\catolimi_deploy -N '""' -C catolimi-deploy
   ```
   공개키(`catolimi_deploy.pub`)를 서버의 `~/.ssh/authorized_keys` 에 한 줄 추가합니다.
   ```powershell
   Get-Content $env:USERPROFILE\.ssh\catolimi_deploy.pub | ssh -i <키.pem> ubuntu@<IP> "cat >> ~/.ssh/authorized_keys"
   ```
2. **서버 지문** 확인: `ssh-keyscan -H <IP>` 의 출력을 복사해 둡니다.
3. GitHub 저장소 **Settings → Environments → New environment** 이름 `staging`:
   - **Deployment branches and tags**: "Selected branches" → `develop` 만. (다른 브랜치의 워크플로가 키를 꺼내 쓰지 못하게)
   - **Environment secrets**

     | 이름 | 값 | 필수 |
     |---|---|---|
     | `STAGING_HOST` | 서버 IP | ✅ (없으면 배포를 건너뜀) |
     | `STAGING_SSH_KEY` | `catolimi_deploy` (개인키) 파일 내용 전체 | ✅ |
     | `STAGING_KNOWN_HOSTS` | 2번 출력 | 권장 |
     | `ANTHROPIC_API_KEY` | Claude 키 (사용 한도를 건 키 권장) | 선택 |
     | `DEEPL_API_KEY` | DeepL 키 | 선택 |
     | `STAGING_ADMIN_TOKEN` | 테스트 서버 관리자 토큰 (아무 긴 문자열). 팀에 알려 주면 각자 테스트 서버 수집을 돌릴 수 있음 | 선택 |
   - **Environment variables** (선택): `STAGING_USER`(기본 `ubuntu`), `STAGING_DOMAIN`(가진 도메인을 쓸 때. DNS A 레코드를 서버 IP 로), `ANTHROPIC_MODEL`
4. 운영과 같은 서버면 클라우드 방화벽은 이미 80·443 이 열려 있어 따로 할 일이 없습니다.
5. **Actions → 테스트 서버 배포 (develop) → Run workflow** 로 첫 배포를 돌립니다. 끝나면 `https://staging.<IP>.sslip.io` 가 나옵니다.

### 쓰는 법

- 지금 떠 있는 코드: `https://staging.<IP>.sslip.io/api/health` 의 `env`(staging)·`revision`(develop@커밋)·`version`. 운영 서버도 같은 주소로 `env: prod` 가 보입니다.
- 지금 바로 수집: `curl -X POST -H "Authorization: Bearer <STAGING_ADMIN_TOKEN>" https://staging.<IP>.sslip.io/api/admin/crawl`
- 푸시 시험: 휴대폰에서 테스트 서버 주소를 홈 화면에 추가 → 설정에서 푸시 켜기. 운영 앱과 별개로 설치됩니다.
- 로그 (관리자): `sudo journalctl -u catolimi-staging -f`
- 배포가 실패하면 GitHub **Actions** 탭의 로그를 봅니다. 서버 테스트가 실패하면 서비스를 바꾸지 않고 멈춥니다.

## 문제가 생기면

- **HTTPS 주소가 안 열림**: 클라우드 방화벽에 443 이 열렸는지 확인 → `sudo journalctl -u caddy -n 50` 에서 인증서 오류 확인. sslip.io 인증서 발급이 막히면 무료 DuckDNS 주소나 가진 도메인을 `-Domain` 으로 쓰세요.
- **scp/ssh 실패**: IP, 키 경로, 사용자 이름(`ubuntu`), 22번 포트를 확인하세요.
- **수집 오류**: `https://<주소>/api/health` 에 게시판별 마지막 수집 시각과 오류가 나옵니다.
